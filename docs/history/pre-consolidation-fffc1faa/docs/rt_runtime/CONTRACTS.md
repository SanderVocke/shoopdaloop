# Runtime contracts and validation matrix

The [runtime book/reference](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/rt_runtime/docs/README.md) describes the current public API. The initial table and A1–A8 evidence below retain their delivered-runtime scope; `DONE_INITIAL_CRATE.md` is historical. The coordination section describes implemented generic extensions, not a new acceptance report. LL-A1–LL-A12 remain the separate loop plan's complete acceptance criteria.

Generic planning, typed pending receipts/recovery, required-render accounting, indexes, capture groups and staged graph authority are implemented. The separate [loop facade](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/shoop_loop_engine/docs/runtime.md) supplies musical policy and prepared-template routing/configuration/program transactions. That is not a generic-runtime dependency or proof of independent loop-host/deadline acceptance.

## Initial API contracts and historical scheduling/budget rows

The Scheduling and Budgets rows retain the initial split-credit/legacy-resource design. They are **not current internal-interval or required-render limits**; use the coordination section below. The Transactions row also records the later staged-publication extension.

| Area | Contract |
| --- | --- |
| Preparation | Validate configuration and checked arena-size arithmetic before allocating render storage. Preallocate/pre-touch all callback-reachable storage. Capacities are immutable while running. Initialization failure does not create a partially usable runtime. |
| Blocks | Planar `f32`; actual frames in `1..=max_frames`; fixed configured host channel counts. Zero frames is a no-op, including no command consumption or clock advance. Invalid shape returns a compact error and clears the writable output prefix without indexing beyond slices. Work on malformed inputs is capped by configured channels/frames. |
| Clock | Unsigned 64-bit absolute sample frames, starting at zero. Nonzero successful blocks advance exactly by their frame count. Reject noncontiguous host positions or arithmetic overflow. Frame positions travel as plain data; no required 64-bit atomic or hidden lock-based fallback. |
| IDs | Typed slot plus nonzero generation. Validate both. Reuse increments generation with checked arithmetic; exhaust a slot rather than wrap. Sequence/epoch/revision exhaustion rejects new mutations; no silent ABA. |
| Graph | Typed DAG; mono audio ports can be grouped/routed as multichannel signals. Deterministic node/source order; sum fan-in without clipping. Missing input/output connections are silence/empty MIDI. Reject cycles, invalid ports, bad references, illegal aliasing, or capacity violations. |
| Transactions | Prepare/stage privately; expected-epoch/revision checked at commit. All reference/range/topological/alias validation finishes before activation. Legacy plan/resource commits occur at callback boundaries. Opt-in validated graph permits can publish at operation/planning boundaries after domain preflight; retain the displaced graph without scanning or destroying it. Retained processor slots preserve state. |
| Scheduling | Absolute-frame parameter/MIDI operations. Queue submission does not promise scheduling. Render admission reserves future-event, split, and execution-result capacity before issuing an accepted scheduling result. The initial conservative outstanding limit is `min(scheduled_events, budgets.events, budgets.subranges - 1)`; unread results retain their slot. Apply on-time admitted events at exact frames; late arrivals apply at the next available frame with lateness reported. Reject excess work before acceptance. |
| Equal times | Stable source/port order, then monotonically increasing per-source sequence. Preserve input FIFO. Parameters at frame F affect sample F; events at block end belong to the next block. |
| MIDI | MIDI 1.0 short/system messages and bounded SysEx bytes; no silent truncation. Fixed event and byte arenas per prepared port. Reject invalid message lengths/data; deterministic merges. Report overflow and reserve capacity for bounded note-release/reset recovery, never silently overwrite note-offs. Recovery uses a separate reserved path emitting CC120 (all sound off), then CC123 (all notes off), on each of 16 channels. Refuse ordinary traffic while recovery is pending; acknowledge each reset packet only after downstream admission. Repeated overflow does not restart an unfinished reset. Runtime integration must preserve these credits independently of ordinary event capacity. |
| Budgets | Independent limits for command processing, scheduled events/subranges, transfer bytes, descriptor-validation steps, and publications per callback. Validate minimum indivisible-work requirements at preparation. Processor resource I/O headroom is reserved within total copy/validation budgets; background staging cannot consume it. DSP work is bounded by admitted nodes/edges/ports and frames; no drain-until-empty loops. |
| Completion | Distinguish submission, scheduling admission, application, and rejection. Include sequence/effective frame/epoch or revision. Reserve terminal-completion storage at submission. Reliable outcomes never compete with lossy/coalesced telemetry for capacity. |
| Ownership | Reserve retirement credits before activating work that displaces ownership. A full queue returns ownership to the caller or retains it in a preallocated slot. No callback final-reference destruction, including errors, cancellation, or dropped peers. |
| Disconnect | Continue the last valid graph and retain bounded storage if the control endpoint disappears. The host owns final teardown and must stop/join callbacks before destroying the render endpoint. No intentional leak fallback. |
| Resource upload | Reserve fixed pages/transfer state; validate bounded chunks, ranges, and sequence. Reject incomplete, malformed, stale, or oversize uploads. Cancellation returns storage through the same safe lifecycle. |
| Resource commit | New revision becomes visible atomically at a block boundary. Playback never observes partial data or a runtime-induced silent block. Sample-value discontinuities are not automatically crossfaded. |
| Capture | Append audio or timestamped MIDI within prepared capacity. At exhaustion, stop capture and mark incomplete, leaving playback and previous snapshots valid. No unlimited recording claim. |
| Snapshot | Lease immutable pages for a coherent revision/prefix cut at an explicit capture frame. A partial tail copy is page-bounded and budgeted. Publication may be pending in the request queue; only a successful reliable reply grants a lease/cut. Immediate over-budget snapshot refusal is not publication. Never report mixed revisions as current. Retaining leases consumes credits and may refuse further capture/snapshots. |
| Publication | Fixed-capacity coherent state slots, bounded attempts, no seqlock retry loop waiting for another thread. Optional telemetry can coalesce with a counter; reliable completions cannot disappear. |
| Processor | Preparation may allocate; process uses borrowed disjoint views and bounded writers only. No RT allocation/deallocation, locks, waits, I/O, logging, or panic on normal errors. User-supplied DSP must uphold this obligation; the type system alone cannot guarantee it. |
| Browser | No shared memory, Wasm threads, or isolation requirement. Wire plans are relocatable descriptors, never heap pointers. Initialize fixed worklet processor slots and Wasm storage before audio. Bound ingress and materialization; recycle transfer buffers by explicit credit. |
| Shutdown | Stop callbacks, cancel/drain pending transfers, release leases, then reclaim all owned objects on a non-RT context. Verify destructor location and credit balance; do not use callback teardown as the reclamation path. |

## Test groups

| Acceptance | Named group / evidence |
| --- | --- |
| A1 | `boundary`: production/build dependency audit; external public-API fixtures; unchanged existing Shoop consumers. |
| A2 | `portable`: common native/Node/Chrome tests; Linux/Windows/macOS CI; actual AudioWorklet on a non-isolated origin. |

| A4 | `graph`: scalar reference executor, seeded DAG generation, invalid descriptors, stale transactions, retained state, variable block partitions, saturated retirement. |
| A5 | `timing_midi`: exact output samples/events, timestamp boundaries, equal-time ordering, late outcomes, byte/event/subrange exhaustion and note recovery. |
| A6 | `resources`: revision/prefix immutability, incremental upload/export, large buffers, pinned leases, capture exhaustion, cancellation and stale commits. |
| A7 | `lifecycle`: small-capacity state machine, peer drops, full queues, destructor probes, two-thread stress, applicable Miri/model checking. |
| A8 | `end_to_end`: same admitted journal across offline/native/worklet, persisted benchmark configuration/results, runnable CI gates and failure canaries. |

Every group must exercise tiny capacities (one/two slots and the minimum valid budget), exactly-full and one-over-limit inputs, and post-failure recovery. Timing tests include different block partitions and long frame counters; resource lengths exceed per-callback transfer limits by at least 16 times. Validation errors must be observable under the same RT guard as success paths.

## Benchmark workloads

Use recorded seeds/configurations, 48 kHz, and block sizes 32, 128, and 512 where supported. Measure idle, gain chains, fan-in/out DAGs, representative 16-node and near-configured-capacity graphs, short-MIDI/SysEx bursts, sustained bounded capture, and concurrent plan/resource staging. Report duration distribution/max and nominal deadline misses, operation/byte/split counters, transfer throughput, peak live storage, and refusal counts. Keep the active graph/data workload identical when comparing baseline versus concurrent control traffic. Timing is diagnostic on a named host, not a brittle CI pass threshold or a claim about the old engine.

## Coordination contracts (implemented generic extensions)

Implemented in the interval milestone: `Planner`, `NoPlanner`, `GraphRuntime<P, L>`, `Processor<L>`, validated planner bindings, immutable interval views, producer-reserved observations, and one callback envelope with positive-progress internal intervals. External event/result capacity is now `min(scheduled_events, budgets.events)`; `budgets.subranges` is ignored. Traversal diagnostics saturate with `counter_overflow`, rather than rejecting configurations based on a worst-case counter estimate. The generic implementation remains domain-independent. Typed planner/processor operations and retained runtime terminal receipts are implemented, with a separate recovery slot and explicit requested/delivered/terminal frames. Queued typed cancellation prevents delivery; pending cancellation completes a retained token. Runtime success and domain outcome remain distinct. The first Stage 4 resource milestone implements restricted required read/capture access and independent saturating work diagnostics while retaining background quotas and legacy behavior. Append-maintained balanced page indexes now provide checked store-scoped byte positioning. Opt-in fixed MIDI checkpoint rows now provide incremental event/state indexing and bounded seek. Prepared group transactions now use exclusive claims, reserved final leases, staged all-member publication, and planner-only frame-bound authority. Generated pool/content models and seventeen lifecycle-cut control disconnect cases verify the generic group ownership contract. Loop adaptation/restoration and prepared-template routing, stopped-owner configuration and paired running-program/graph publication live in the separate loop library. They do not construct arbitrary physical processors or resize ports. See [loop validation](../loop_layer/VALIDATION.md) for historical tests/interpreter/prototype/host-regression scope, not a new campaign implied by this contract.

| Area | Current contract / existing verification scope |
| --- | --- |
| Planning | One generic prepared planner with a no-planner default; explicit catalog/descriptor planner-consumer bindings. Synthetic planner tests must prove ordering without dummy signal edges, stale-ID refusal, and lifetime-safe decision/observation access. |
| Callback envelope | Snapshot admission/recycle credits/reset maintenance and recovery allowances once. Select positive internal intervals up to the next external action/host end. Dense internal intervals cannot exhaust an arbitrary subdivision allowance. Finish observations at callback end; settle that boundary before the next rendered sample. |
| Typed operations/results | Domain operations are typed plain data, not magic float parameters. Requested/effective/delivered/terminal frames differ; delivery lateness excludes Pending wait. Runtime success can carry domain refusal. A delivered pending operation retains its reliable terminal receipt; automatic transitions consume no external credits. Recovery has one independent finite slot and must terminate at delivery-frame planning before positive samples. |
| Scheduled ordering | Effective frame, target/category/subkey, then sequence. Planner targets precede processor actions; per processor parameters precede MIDI then typed operations. Lane recovery priority changes transport admission, not this scheduler key or global category order. |
| Fixed storage | Retain checked preparation capacities and immutable run-time storage for media, indexes, descriptors, views, observations, requests, and results. Refuse insufficient preparation explicitly; do not reinterpret a wave/subdivision CPU cutoff as a storage requirement. |
| Background allowances | Command service, uploads/exports, descriptor/program validation, optional publication and reclamation remain callback-budgeted. Eligible snapshotted recovery parks a held normal head inline with its owner/progress/original cancellation observation, then resumes it before later normal work. Limits and cancelled-recovery costs remain; endless recovery need not be fair. A held command cannot wait for later upload input. |
| Required rendering | Prepared reads/index lookup, capture appends/checks, exact-frame activation/freeze, and finite internal transitions are counted but not throttled by a background quota. Verify tiny background allowances do not interrupt otherwise provisioned musical execution. |
| Resource transactions | Version-scoped indexes and exclusive managed capture writers; group preflight before dependent samples, common-prefix append/freeze, reserved playback readiness, immutable old leases, and explicit failure/retirement. Test no whole-resource scan or asynchronous gap at record-to-play. |
| Graph activation | Fixed staged-owner slots, incremental validation at an expected epoch, scoped nonwrapping identities, checked actual-capacity budgets and reliable owning release. A borrow-scoped permit rechecks current/validated epochs and pending MIDI compatibility, reserves retirement, then commits infallibly after all fallible domain work. Recovery operations cannot activate. Operation-time removal makes later injection InvalidId; planning-time removal after injection is Busy, preserving old-graph consumption once. No automatic note/pedal cleanup follows routing. |
| Boundary preview | Provisional reservations/shadow state are not externally committed. A re-preview must latch an additional previously unlatched prepared group/activation failure; no duplicate pulse, receipt completion, generation advance, or publication. Musical failure decisions precede affected samples. |
| Diagnostics | Counts may saturate with an overflow flag; observation limits never change musical execution. Semantic frames/IDs/revisions still use checked exhaustion, not wrapping or diagnostic-style saturation. |
| Fault/claim boundary | Publication/time may advance before an error; never replay, invent finish or assume cleared output means no mutation. Fixed storage and finite application-dependent work are not a deadline guarantee. Planners, like processors, must honor termination/callback-safety obligations; safe Rust alone does not prove them. |

Preparation may compile/install an initial signal/planning graph through `GraphRuntime::prepare_with_initial_graph`: the returned runtime starts at epoch one/frame zero with no warm-up callback, scheduling receipt or ingress credit consumed. All preparation validation and rejected-owner destruction occur off-render. Normal later graph changes retain expected epochs, incremental validation and reliable owning returns. Quiescent `into_planner_and_resources` retains the planner ledger and resource store for explicit domain cleanup while other runtime owners are destroyed off-render; it does not settle pending work or emit cleanup to a stopped device.

The production graph-capability prototype is `docs/loop_layer/prototypes/graph_activation_lifetime.rs`: positive execution and five compile refusals cover retained graph/candidate/permit views, escaped authority and private construction. The corresponding guide is [chapter 15](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/rt_runtime/docs/part-4-coordinate-processors-and-changes/15-staging-and-coordinating-graph-activation.md). This capability swaps graph metadata, not arbitrary processors/resources or unvalidated domain state.

The generic lifetime prototype is `docs/loop_layer/prototypes/interval_lifecycle.rs`; the integration/ownership specification is `docs/loop_layer/RUNTIME_INTEGRATION.md`. Musical clock/coalescing/conflict rules belong to the loop layer. Prototype success is not proof of production resource, scheduler, graph-validation, or AudioWorklet behavior. The simplified interval prototype and production graph-capability prototype have different scopes. Existing evidence retains its source/run meaning; these documentation corrections do not certify new models, callback audits, canaries, platform runs or loop-host acceptance.
