# Coordinated loop facade — implementation design

The coordinated facade and constrained Stage 6 publication paths are implemented in shoop_loop_engine::runtime: typed control, separate playback/capture consumers, coherent state/export, fixed-role routes, stopped-owner configuration, selected-program/graph cuts and permanent cleanup. This document records choices, not a change to PLAN_LOOP_LAYER.md acceptance. Public preparation/operations are in the [runtime guide](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/shoop_loop_engine/docs/runtime.md) and [activation guide](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/shoop_loop_engine/docs/topology-activation.md).

Historical facade-stage5{,-provenance}.json records ten guarded cases, 25 broad gates, 159 selected interpreter executions, proofs/failures and generic-host regressions. Later [Stage 6 completion](STAGE6_READINESS.md) records its own consolidated source/run scope; neither is a new audit/platform campaign. The unchanged coordinated_loop example has no allocator guard of its own. Independent loop hosts/benchmarks and newer performance/deadline evidence are not supplied in this snapshot.

## Ownership and preparation

- One loop planner contains the resolver, fixed media-binding/receipt/failure scratch, and coherent public state. Runtime frames remain authoritative; only resolver decisions determine musical modes/positions.
- Playback and capture are distinct processors. A capture processor continues observing connected MIDI input while stopped, so its last completed input projection describes state strictly before the next boundary. Current-interval input events remain events, not initial capture state.
- Each media-bearing primitive has two prepared capture groups with distinct resources. Repeated Record starts a new logical capture revision even when already recording. An alternate idle group permits preparation of the replacement before the old take freezes; never mutate the leased playback revision in place.
- `media::Ledger` now implements a fixed media-slot pool owning snapshot leases once. Playback, latest completed take, prepared replacements, pending-request pins and external exports reference those slots through checked identities/refcounts. Pending pins and exports have independent fixed pools; playback/latest roles are separate per-loop rows. See the loop crate's [media ownership guide](https://github.com/SanderVocke/shoopdaloop/blob/fffc1faaf44f22aec32a66848cc5eb97c2ee7f9a/src/rust/shoop_loop_engine/docs/media.md). A slot releases its underlying snapshots exactly once when no reference remains. This avoids inventing a second media store or duplicating a lease merely to retain a frozen revision for export.
- Reserve a media metadata slot as well as generic take versions/index rows/final leases before promising capture activation. Storage exhaustion is an explicit domain refusal; no external completion credit is needed by autonomous starts/wraps.
- Prepare/read-validate imported audio/MIDI snapshots off-render: formats, channel counts, shared duration, scope and MIDI indexing. Domain take revisions are distinct from the resource revisions incremented by interval commits. The facade reserves imported revision identities in the resolver's watermark before future capture allocation; the ledger itself neither allocates domain revisions nor infers whether inputs are the same logical take. Prepared replacement operations select validated resident media, rather than trusting arbitrary lengths/revisions supplied by a command. Any zero padding of short imports is materialized explicitly by the caller off-render; the facade has no automatic padding option.

## Stable boundary execution

1. Deliver the finite admitted typed operations and retain runtime receipt tokens for unresolved resolver requests. Reserve an independent domain recovery slot as well as the runtime's recovery reservation.
2. Recheck pending selected-program/graph candidates at the actual cut, without treating Ready as locked. Preview the resolver at the runtime ceiling. Compare committed and candidate capture revisions to identify new takes, restarts, finishes and continued recording; do not infer changes from the optional journal.
3. Prepare new takes using the input projection at this boundary. Reserve their first intervals with `reserve_prepared`; reserve continuing takes normally. Keep provisional take/metadata owners across retries when still applicable, but cancel provisional intervals before re-previewing a different interval.
4. Latch failures in fixed scratch. For an authoritative request-origin family, use `Refused`; for an autonomous capture start, use `CaptureUnavailable`; for a failed append to an existing take, use `CaptureExhausted`. Refused restart and old-take exhaustion may coexist. Every retry adds a previously unlatched failure. No arbitrary retry/subdivision cap or callback-credit reset is permitted.
5. Once stable, freeze ended takes at F, activate prepared replacements at F, update pinned playback bindings, and commit the resolver once. A record-to-play decision must see the new immutable indexes before sample/event F. Empty record-to-play remains the resolver's refusal, not an empty freeze followed by silence.
6. Publish immutable decisions to playback/capture consumers, render the actual signal DAG, and commit staged capture groups in finish before advancing the resolver. Input state, overflow/incomplete observations and public cuts must use the same interval and checked producer identity.

Conservative MIDI reservation may fail earlier than an exact future-output bound, as already documented by the generic capture contract. With sufficient prepared resources, interval invariance remains mandatory. Capacity failures must still preserve a truthful common prefix and affect dependent decisions before samples cross their boundary; no retroactive rollback is available.

## Receipts, observations and coherent export

- `ReceiptToken::sequence()` supplies request ordering. Preserve requested, scheduler-effective, actual delivered and musical terminal frames; delivery lateness excludes Pending wait and successful runtime delivery may carry domain refusal. A resolver result can be inspected after commit and forwarded at F; recycle the resolver's retained completion after finish, because its `take_completion` API intentionally forbids mutation while decisions are committed/borrowed.
- Cancellation distinguishes queued runtime work from already-delivered resolver requests. The exact facade recovery-safe set is Cancel, TopologyCancel, RoleCancel, RoleSourceRelease and nonfuture Timing::At Stop; all are payload-free and terminate by delivery-frame planning before positive samples. This needs neither another normal domain slot nor normal unread-result credit. Callback-start eligible recovery parks a held normal owner/progress/cancellation observation, then resumes it before later normal work; finite command/publication allowances still apply and continuous recovery need not be fair. Ticket cancellation, cancel_queued and delivered Sequence cancellation are different cuts; standalone RequestId is not the facade cancellation argument.
- Public State/Export use one defined observation phase, not a public phase enum. Use the implemented post-settlement, pre-render cut at F so simultaneous transitions and frozen media agree. Cut contains frame/epochs, State, borrowed playback/latest identities, gain and capture/MIDI failure diagnostics, with no AfterInterval field. Optional publication failure must not stop musical execution.
- Export tokens retain media-slot ownership, not borrowed pointers or an unpinned copy of a snapshot ID. Existing runtime resource requests perform bounded reads into owning return buffers. Releasing an export invalidates its checked token and decrements the media reference.
- An active recording snapshot acquires all channel prefixes at the same boundary without interleaved rendering. If optional acquisition fails partway, release unpublished temporary leases and return a truthful refusal; never publish a partial group. Tail-copy work remains background-accounted. Frozen playback export can retain an existing media slot without copying content.

## Graph and lifecycle integration

- Initial preparation must establish validated planner bindings and the actual signal graph before musical execution begins, rather than hiding a silent warm-up interval. `GraphRuntime::prepare_with_initial_graph` now provides the generic preparation path: it compiles/validates the graph and bindings off-render and returns epoch one at frame zero. Facade role validation now precedes it.
- The facade must validate required capture/input-tracking consumers, expected decision slots and media shapes. A generic structural descriptor alone does not prove domain role correctness. Do not expose unrestricted graph replacement as though these additional invariants had been checked. The implemented live graph/topology/program/configuration paths preflight these invariants over fixed prepared physical templates; none constructs arbitrary processors or resizes ports on-render.
- TopologyActivate changes fixed-ID/kind timing only after changed programs are already stopped; ProgramActivate owns a selected program until a stopped/real-zero cut. GraphActivate changes compatible fixed-role routes immediately and can continue recording; TopologyGraphActivate pairs immediate timing/routes. ConfigurationActivate edits already-stopped logical generations/media with matching timing/routes; a same-frame queued Stop has not settled. ProgramGraphActivate pairs one selected program/routes at actual zero/stopped entry, leaving IDs/kinds/sync/triggers/other programs and physical roles fixed.
- Role/source, timing, graph and external export owners have independent lifetimes. Successful RoleAppend consumes its source IDs; rejection transfers none. OwnerActivation preflights a whole batch using currently free metadata, not anticipated old-retirement credits. Complete every fallible check before publication; unused permits transfer nothing but cannot undo arbitrary application changes. Old-generation exports remain immutable and explicitly leased.
- Audio consumers need safe direct `AudioPorts` access without allocating temporary vectors of channel borrows or retaining callback references. `AudioRenderer::render_ports` and `AudioCapture::stage_ports` now share conversion/DSP logic with the existing slice APIs through scoped adapters. The separate playback and capture consumers use those adapters.
- Quiescent teardown must retain the planner's owner ledger while extracting resources. `GraphRuntime::into_planner_and_resources` now returns both planner and store off-render. `Stopped::cleanup` explicitly cancels/freezes/releases groups, media and exports from that retained ledger rather than dropping the only copy of their handles. This cleanup permanently quiesces, is repeatable, and preserves actual state/time/prefixes even after publication followed by render failure. It neither fabricates finish/outcomes, rolls back, replays samples nor makes a resumable pause. Imported resources remain caller-owned. Device cleanup still occurs before stopping callbacks; extraction cannot emit MIDI to a stopped device.

## Verification

Historical Stage 5 evidence verifies the public lifecycle example and separate playback→gain/FX→capture nodes; the example itself has no heap guard. The integrated cases check stereo plus MIDI record→immediate play, wraps, seeks, prepared replacement, stop cleanup, coherent exports, repeated recording, resource refusal/isolation and complete owner recovery. Independent sample/packet/content expectations agree across host partitions and valid declaration orders, with journal exhaustion and stalled external results. The ten full workloads pass native debug/release, Node/Chromium and selected Miri with heap/destructor guards. See the Stage 5 completion section of `VALIDATION.md` for exact evidence, retained failures and scope. Later configuration, paired-program/graph and nested scenarios are scoped separately in VALIDATION.md. Existing generic fixtures/package-Wasm tests/offline examples do not substitute for an independent loop host, which is absent here.
