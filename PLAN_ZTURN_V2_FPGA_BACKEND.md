# MYIR Z-turn V2 FPGA looping backend

Baseline `origin/feat/backend-replacement` at `bdaea8c3`. The target is the MYIR Z-turn V2 with the XC7Z020-2CLG400. The firmware control endpoint runs on one Cortex-A9 under FreeRTOS with the existing AMD lwIP port and Shoop network protocol. The current state processor, job processor and media pipeline run in programmable logic (PL). Keep the native FreeRTOS renderer as a separate build for bring-up and comparison. Start with deterministic generated audio, then qualify physical audio through an external I²S codec. Verify the provisional codec wiring against the populated board before bench use.

Use the published 1 GiB MYIR schematic marked Ver 1 and the Digilent Pmod I2S2 as the provisional board and codec combination. The assumed module uses a CS5343 ADC and CS4344 DAC with 3.3 V digital signaling. Confirm the populated revisions, connector pinout, FPGA I/O bank voltages and available JTAG/UART before testing that wiring. [MYIR schematic](https://www.myirtech.com/down-load1.asp?id=1027) · [Digilent Pmod I2S2](https://digilent.com/reference/pmod/pmodi2s2/reference-manual)

The first release covers record, play, stop, loop gain, supported sync plans, and live edits to graphs accepted by the current FPGA compiler. Additional endpoint features such as MIDI, processors, composites, and media import/export can follow. Treat 64 active loops as an explicit performance workload. Publish the largest tested configuration that satisfies the deadline and capacity gates, including the result or precise limiting resource for the 64-loop case. [Current FPGA host scope](src/rust/shoop_host/README.md#rust-fpga-reference-with-the-ui) · [MYIR board specifications](https://www.myirtech.com/list.asp?id=708)

## Acceptance criteria

1. Reproducible ELF and bitstream builds target the exact MYIR part and board revision, with a matched SD boot image. The board cold-boots, initializes DDR and Ethernet, and accepts the existing authenticated client. The same board profile builds and boots a native comparison ELF.
2. The client can record nonzero audio, stop, play, adjust loop gain, apply a supported sync plan, and edit a running graph while a continuing loop retains its take and playback state. Unsupported graphs fail through the existing control protocol and preserve the active graph. The same operations produce expected command outcomes, effective frames, coherent snapshots and exact Q8.24 sample vectors in the deterministic FPGA test path.
3. A live switch applies at a quantum boundary. The completion releases the old allocations only after the memory fence. Saturated command and response queues preserve ordering and terminal outcomes. Fault handling silences output, preserves ownership until safe recovery, rejects stale work after reset, and recovers through a bounded restart. These behaviors have simulation tests plus board smoke coverage.
4. The complete routed image meets setup and hold on the MYIR part, passes design and clock-domain crossing checks, and reports usable capacity and clock rate to the firmware. With physical audio at 48 kHz and Q=32, the advertised workload completes every quantum within 667 µs with zero xruns during a 30-minute run that includes recording, playback, live edits, and competing Ethernet traffic. Publish worst-case quantum time, deadline misses, control latency and ARM load. Run the native comparison on the same board with the same input, graph, rate and processing quantum. Include its misses in the comparison.

## Design rules

- Keep graph compilation, logical identities, allocation and the application protocol on ARM. Reuse `RtBackend`, the reference endpoint and `ProgramLoader`, the compiler, and RTL image packing. Extract the portable code from the Marlin owner behind a typed device interface that compiles for `armv7a-none-eabihf` with `core` and `alloc`. Keep the simulator’s model, clock and thread machinery in its host adapter.
- Use `M_AXI_GP0` with AXI-Lite for discovery, status, command and completion queues, and doorbells. Connect the current core’s 64-bit AXI3 master to `S_AXI_HP0` for media and metadata in reserved PS DDR. Generate matching firmware and RTL constants from one versioned board and bridge description. Include arena bounds, capacities, target clock and compatibility identity. Keep the media arena PL-owned initially. Specify MMIO ordering, address validation, and cache maintenance at any ARM/PL buffer ownership transfer.
- Give the PL audio scheduler the sample clock and quantum cadence. Apply bounded command groups before a quantum, use the existing switch handshake with `run_valid`, and return the effective frame and fenced completion. Export and consume sync events explicitly. Capture coherent frame- and revision-tagged state into alternating buffers. Calculate peaks in PL or batch their transfer so snapshot and meter reads stay off the audio deadline. Service control via a PL-to-PS interrupt and FreeRTOS notifications after the initial register smoke test.
- Keep register, queue and audio storage bounded and preallocated on the deadline path. On a controlled reset, stop new AXI work, drain outstanding transactions, then reset and start a new generation. When a bus fault prevents draining, keep the arena reserved until the PS/PL reset boundary establishes that ownership can safely restart. Derive Linux fixture and board limits from the configured geometry. Use the historical ZedBoard bridge for bus, reset and diagnostics patterns and the current loading contract for behavior. [Current loading contract](LOADING_DESIGN.md) · [Historical bridge and register capture](https://github.com/SanderVocke/shoopdaloop/blob/1b34d6acafcb7cb241923f9d933367b62bd2e93f/fpga/host_bridge/README.md)
